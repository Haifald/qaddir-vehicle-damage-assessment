  damage-to-part association, verification, LLM generation, output guarding,

  the frozen prompt.
- Added centralized environment configuration and tests for matching,
  verification, and report grounding.
- Added fail-closed report gating for hedge-band, ambiguous-association, and all
  other manual-review records.
- Made Ultralytics confidence, image size, and device explicit configuration,
  and made health checks load both models and validate their class vocabularies.
- Updated project status, architecture, local-run instructions, and known gaps.

## Data flow

The upload API validates image format, size, and minimum resolution before any
model call. Configured production damage and part models then produce detections
that are normalized into the provisional `Ruba` contract. A deterministic
box-coverage baseline creates association candidates. Verification checks the
closed taxonomies, identifiers, references, contradictions, and configured
confidence policy. Rejected records never reach the LLM.

Only a record with verification status `verified` is LLM-eligible. Manual-review
records retain their structured findings in the API response but receive a
blocked report state. For an eligible record, the application runs the teammate's manifest verifier,
loads the frozen Prompt V2 from its original path, injects configured production
thresholds, and sends only the verified JSON to the LLM. A final report guard
suppresses output containing unsupported severity, repair, cost, safety, damage,
or part claims. The API returns the structured evidence and report state to the
frontend.

## Local run

```powershell
py -m venv .venv
.venv\Scripts\Activate.ps1
pip install -r backend\requirements.txt
Copy-Item .env.example .env
# Populate .env with reviewed checkpoint, inference, threshold, and LLM values.
uvicorn qaddir_api.main:app --app-dir backend --env-file .env --reload

cd frontend
npm install
npm run dev
```

Configuration variables are documented in `.env.example`.

## Not connected or calibrated

- Production-trained checkpoint files are not in the repository.
- The damage-model production selection is still open.
- The overlap matcher is an integration baseline, not a calibrated matcher.
- Production thresholds are intentionally unset.
- CV inference confidence and image size are intentionally unset until they are
  selected against the real checkpoints; device is also explicit configuration.
- The frozen prompt is still on `origin/Ruba` and was not merged.
- The LLM API key and model are intentionally unset.
- Ruba's frozen prompt was evaluated on Claude Sonnet 5 and must be re-evaluated
  on the exact OpenAI model before presentation use.
- Severity is not supported by current evidence and remains `null`.

No simulated detections or reports were added.
