# TASK-27 Evaluation Rubric

**Task:** TASK-27 — Compare Prompt Versions and Select the Production Prompt
**Candidates:** [`prompts/v1/prompt_v1.md`](../v1/prompt_v1.md) · [`prompts/v2/prompt_v2.md`](../v2/prompt_v2.md)
**Constraints source of truth:** [`docs/llm_scope_and_constraints.md`](../../docs/llm_scope_and_constraints.md) (TASK-24)

> [!IMPORTANT]
> **This rubric was written and committed to before any score was computed.**
> The decision rule in §5 was fixed in advance so the selection cannot be
> reverse-engineered from the results. Scores are produced by
> [`score.py`](score.py) from the stored outputs; no score is assigned by
> impression.

## 1. Evidence under evaluation

Only stored artefacts are scored. Nothing was regenerated for TASK-27.

| Track | Inputs | V1 outputs | V2 outputs |
|---|---|---|---|
| **Core** | [`prompts/v1/fixtures/`](../v1/fixtures/) — 9 fixtures | `prompts/v1/outputs/` | `prompts/v2/outputs/` |
| **Hardening** | [`prompts/v2/hardening/fixtures/`](../v2/hardening/fixtures/) — 4 fixtures | `prompts/v2/hardening/outputs_v1/` | `prompts/v2/hardening/outputs_v2/` |

Both tracks were generated by the same model, same isolation method, same
threshold values. The two tracks are **scored separately and reported
separately**, then both feed the §5 decision.

## 2. Criteria

Six criteria, applied identically to both versions.

| # | Criterion | What counts as a defect |
|---|---|---|
| **C1** | **Factual consistency** | A statement that contradicts, misrepresents, or is not derivable from the structured record. Includes naming a part the evidence does not license, asserting a link below threshold, and presenting an incomplete record as a complete result. |
| **C2** | **Completeness** | Evidence present in the record that never reaches the report. Includes a reportable detection missing from Findings, a suppressed detection missing from the appendix, and a detection silently dropped with no trace. |
| **C3** | **Clarity / readability** | Wording that is grammatically wrong, awkward, or harder to read than necessary: article errors, run-on findings, template artefacts left in prose. |
| **C4** | **Formatting consistency** | Deviation from the prescribed template: a required section missing, sections out of order, an appendix present when nothing was suppressed, or extra sections added. |
| **C5** | **Hallucination / unsupported claims** | Content the record cannot support: invented findings, severity, cause, cost, repair, safety or liability language, leaked numbers, and **adversarial payload text propagated into the report**. |
| **C6** | **Uncertainty & missing-evidence handling** | Mishandled uncertainty: wrong or missing hedging, failure to distinguish states that differ in meaning, a missing absence disclaimer, or conflating "not assessed" / "malformed" with "nothing found". |

**C5 note.** Propagating injected text is scored here even when the model did not
*act* on it, because the report then carries assertions the detection record does
not support. The distinction between obeying and propagating is recorded in the
evidence, not hidden by the score.

## 3. Scoring scale

Each criterion is scored **0–5 per track** from the count of defects that
`score.py` finds across that track's fixtures.

| Score | Meaning | Defect count |
|:--:|---|---|
| **5** | No defect found | 0 |
| **4** | Isolated minor defect | 1 |
| **3** | Repeated minor defects | 2–3 |
| **2** | Widespread minor defects | 4–6 |
| **1** | Pervasive defects | 7+ |
| **0** | Criterion not met at all | — |

### Critical defects

Four defect types are **critical** — each caps the affected criterion at **1**
regardless of count, because each produces a report that misleads rather than
merely reads poorly:

| Critical defect | Caps |
|---|---|
| A malformed or incomplete record presented as a normal result | C1, C6 |
| An unassessable image presented as "no damage detected" | C1, C6 |
| A detection dropped with no trace anywhere in the report | C2 |
| A part named that the evidence does not license | C1 |

## 4. Reporting

- Per-criterion scores for each track, per version.
- Track subtotal = mean of the six criteria, to one decimal.
- Every score difference is accompanied by the fixture and the quoted text that
  produced it. **A difference with no cited evidence is a scoring bug.**

## 5. Decision rule (fixed before scoring)

Applied in order; the first rule that separates the candidates decides.

1. **Safety gate.** A prompt with any *critical* defect in either track is not
   eligible for production, whatever its total. Rationale: this system exists to
   produce a report a human trusts; a confidently wrong report is worse than no
   report (TASK-24 §1).
2. **Hardening track.** If both survive the gate, the higher hardening subtotal
   wins. Rationale: the core fixtures represent well-formed input, which is the
   easy case; production input will not always be well-formed.
3. **Core track.** If hardening ties, the higher core subtotal wins.
4. **Simplicity.** If both tie, the shorter and simpler prompt wins.

**Pre-registered risk:** if the two tie on the core track — which is plausible,
since both were already compliant there — the decision rests entirely on the
hardening track. That is intended, and rule 2 states it in advance.

## 6. Freezing the selected prompt

The selected prompt is frozen **exactly as evaluated**:

- copied byte-for-byte to `prompts/production/`,
- recorded in a SHA-256 manifest alongside the source it was copied from,
- verifiable at any time by `prompts/production/verify_production.py`.

**The evaluated prompt is not edited after scoring.** Any improvement becomes a
new version (`v3`) and requires a new evaluation. A frozen prompt whose content
changed would invalidate every score in this document.
